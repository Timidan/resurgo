# Dispatch for Timidan/resurgo

This release establishes the core resurgo runner and repair loop, adds automated patch verification and tracing, and introduces the web dashboard alongside the GitHub App installation pipeline.

## [Timidan/resurgo](https://github.com/Timidan/resurgo)

### Repair Agent and Verification

- Upgraded the repair agent through version 2.4 and incorporated repository context from entire-graph search into the repair loop.
- Bundled the entire-graph plugin into the execution container to support full graph analysis during repair attempts.
- Enforced strict patch rejection rules against fixes that gut files, weaken test assertions, or fall below 0.5 confidence.
- Added sandbox verification for candidate fixes, recording owner reviews in `runs/reviews.json` while holding verified patches for approval.
- Integrated LangGraph orchestration alongside a model gateway chat client that tracks estimated token usage.

### Runner Infrastructure and Execution

- Implemented the core container runner to execute clean clones and project verification in isolated environments.
- Added a sweep runner to process development and held-out repository lists sequentially with aggregate summaries.
- Configured toolchain detection with support for Bun workspaces, pinned pnpm 9 lockfiles, and root-installed Rust toolchains.
- Raised resource limits to 6 GB memory, 25-minute execution time caps, and expanded Node heap allocations.
- Automated environment file regeneration from `.env.example` on every pipeline execution.
- Added pull request generation guarded by application authentication and structured run records.

### Telemetry and Observability

- Integrated neatlogs tracing across workflows with dedicated spans for container execution steps.
- Recorded neatlogs trace identifiers within output run results.
- Preserved partial step output upon task timeout to assist in failure diagnostics.

### Web Dashboard and User Interface

- Shipped the web application with an interactive run replay hero, run gallery, and diff inspection views.
- Introduced the Daylight lab theme featuring light-by-default styling, saved theme toggles, and tokenized color palettes.
- Added gallery filtering by repository, agent version, run set, and verification status.
- Refined responsive layouts down to 360 px viewports with 44 px coarse touch targets and single-column mobile grids.
- Added error boundaries across landing page sections and the primary route outlet.
- Exposed read-only run API routes alongside `/index.md` and `/llms.txt` endpoints.

### GitHub App Integration

- Created the GitHub App installation callback handler to queue incoming repository checks sequentially.
- Built the dedicated `/installed/:id` page to display live check status, queue reasons, and processing timestamps.
- Published the data storage disclosure page linked across the installation workflow and site footer.

These updates solidify the automated repair and evaluation pipeline while delivering a complete interface for tracking live repository runs.
