1. **Block fixes that weaken tests.** In the v1 held-out sweep, two Foundry repos were recorded as fixed, but only because the model added test exclusions (`no_match_path` and similar) to `foundry.toml`. Their failing tests need a local Ethereum RPC endpoint. The v2 prompt already forbids this, but a prompt is not a guard. Before applying any proposal, reject it if it:
   - adds or changes a test filter in `foundry.toml` (`no_match_test`, `no_match_contract`, `no_match_path`, `match_test`, `match_contract`, `match_path`);
   - deletes a test file (under a `test/` or `tests/` directory, or named `*.t.sol`, `*.test.*` or `*.spec.*`); or
   - changes the `test` script in a package.json.

   Feed the rejection back to the model once, as described in item 3, with the reason "this skips or weakens tests". A second weakening proposal ends the run as broken, with the reason recorded. Renaming or rewriting a test so that it still runs is allowed, for example migrating `testFail*` to `vm.expectRevert`. That counts as a code change and waits for approval.
2. **Record external services as gaps, not fixes.** Let the model answer `{"kind": "gap", "reason": "<the service or credential the step needs>", "rationale": ..., "confidence": ...}`.
   - Accept it only when the install and build steps have passed and the failing step is test or serve. The run then ends as `runs_with_gaps`, with `needs <reason> (<step> step)` in `gaps`, no fix applied and no patch.
   - Reject a gap answer for any other step.
   - Describe the option in the SYSTEM prompt in one or two plain lines.
3. **Re-ask on malformed proposals instead of stopping.** In the v2 development sweep, electron-vite-monorepo ended after a single proposal whose package.json content was not valid JSON. Handle a malformed proposal the way an invalid-JSON reply is handled today: re-ask once with the exact error, and end the run only on the second failure. A malformed proposal is invalid JSON content in a proposed package.json, or a lockfile with model-written content. The weakening rejections from item 1 use the same single re-ask.
4. **Add a native-module rule.** In the v2 development sweep, agent-arena regressed. v1 fixed it by pinning Node 20, but this time the model went after dependencies instead. In the premise check, better-sqlite3 9.6.0 failed to compile on Node 24 and built on Node 22.

   - The rule writes `.nvmrc` with 22 as one rule attempt, before the model is asked. If that still fails the same way, the model takes over as today.
